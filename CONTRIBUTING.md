# Contributing

Read README and docs/IMPLEMENTATION_MASTER_PLAN.md. Use locked dependencies and
the documented verification commands. Keep original reports as historical evidence.
Add focused regression tests for changes; security/data safety takes precedence
over convenience. No production data or secrets in fixtures, issues or logs.

Describe actual test evidence and limitations in pull requests. Do not claim
unrun integration/container/live Supabase checks pass. Do not remove assertions or
security controls to make a check green. Release publication requires owner approval.
Report suspected vulnerabilities privately to the repository owner, with sanitized
reproduction evidence rather than public credentials.
